# iOS 项目设置指南

## 方法一：使用 Capacitor（推荐）

Capacitor 可以将你的 React Web 应用打包为原生 iOS 应用，并自动生成 `.xcodeproj` 文件。

### 步骤 1: 安装依赖

```bash
npm install @capacitor/core @capacitor/cli @capacitor/ios
```

### 步骤 2: 初始化 Capacitor

```bash
npx cap init
```

按照提示输入：
- App name: Wing
- App ID: com.wing.journal
- Web dir: dist

### 步骤 3: 构建 Web 应用

```bash
npm run build
```

### 步骤 4: 添加 iOS 平台

```bash
npx cap add ios
```

这会自动生成 `ios/` 目录和 `Wing.xcodeproj` 文件。

### 步骤 5: 在 Xcode 中打开

```bash
npx cap open ios
```

或者在 Finder 中打开 `ios/Wing.xcodeproj`

## 方法二：手动创建（不推荐）

如果你需要完全原生的 iOS 项目，需要：
1. 在 Xcode 中创建新项目
2. 手动迁移所有代码到 Swift/SwiftUI
3. 重新实现所有功能

这需要大量工作，不推荐。

## 两种方式对比

| 对比项 | 方法一：Capacitor | 方法二：手动创建 |
|--------|------------------|------------------|
| **开发时间** | 快速（几分钟） | 耗时（数周至数月） |
| **代码复用** | 复用现有 React/TypeScript 代码 | 需要完全重写为 Swift/SwiftUI |
| **维护成本** | 低（只需维护一套代码） | 高（需要维护两套代码） |
| **学习曲线** | 低（使用现有技术栈） | 高（需要学习 Swift/iOS 开发） |
| **原生性能** | 良好（WebView + 原生桥接） | 最佳（完全原生） |
| **原生功能访问** | 通过插件访问 | 直接访问所有原生 API |
| **项目复杂度** | 简单（自动化工具） | 复杂（手动配置） |
| **跨平台支持** | 支持（可同时支持 Android） | 仅 iOS |
| **UI 框架** | React + Web 技术 | SwiftUI/UIKit |
| **适用场景** | Web 应用快速打包为原生应用 | 需要极致性能或复杂原生功能的应用 |

### 详细说明

#### 方法一：Capacitor 的优势
- ✅ **快速上手**：几分钟内即可将 Web 应用打包为 iOS 应用
- ✅ **代码复用**：无需重写，直接使用现有的 React/TypeScript 代码
- ✅ **统一维护**：Web 和移动端共享同一套代码库
- ✅ **跨平台**：同一套代码可同时支持 iOS 和 Android
- ✅ **生态丰富**：有大量现成的 Capacitor 插件可用

#### 方法一：Capacitor 的劣势
- ❌ **性能限制**：基于 WebView，性能不如完全原生应用
- ❌ **原生功能**：某些深度原生功能可能需要额外开发插件
- ❌ **包体积**：通常比纯原生应用体积更大

#### 方法二：手动创建的优势
- ✅ **极致性能**：完全原生，性能最优
- ✅ **完整访问**：可访问所有 iOS 原生 API 和功能
- ✅ **包体积**：通常比混合应用更小
- ✅ **用户体验**：完全符合 iOS 设计规范

#### 方法二：手动创建的劣势
- ❌ **开发成本高**：需要完全重写所有代码
- ❌ **维护成本高**：需要维护两套独立的代码库
- ❌ **学习成本高**：需要掌握 Swift 和 iOS 开发
- ❌ **开发周期长**：从零开始需要数周至数月
- ❌ **无法跨平台**：iOS 和 Android 需要分别开发

### 推荐选择

- **选择方法一（Capacitor）**：如果你的应用主要是 Web 应用，需要快速支持 iOS，且对性能要求不是极致
- **选择方法二（手动创建）**：如果你需要极致性能、复杂原生功能，或者已经有 iOS 开发团队

对于大多数 Web 应用项目，**强烈推荐使用方法一（Capacitor）**，因为它能快速实现目标，且维护成本低。

## 注意事项

1. **需要 macOS 和 Xcode**：iOS 开发只能在 macOS 上进行
2. **需要 Apple Developer 账号**：用于真机测试和发布
3. **Capacitor 限制**：某些原生功能可能需要额外的插件
